# Mac 原生 MapKit 对点校准

运行 `sh tools/mapkit-calibration/build-macos.sh` 后，Finder 打开 `.build/MapKit对点校准.app`。不需要高德 Key 或 MapKit JS Token，不请求 GPS；原生 Apple 底图需要联网。

1. 打开 CAMAP，或填学校 ID 读取正式发布版本。修改发布图请优先读线上版本，以保留 masterId/baseRevision。
2. 在 CAMAP 地标列表选择一个具体门或建筑顶点；左侧显示确切位置。相同名称附带 UUID，不能只靠名称认定同一门。
3. 将它选为锚点，点击“在 Apple 底图点同名位置”，再在右侧底图点同一个实体位置。用一个锚点拟合平移，旋转固定为候选旋转，几何坐标不改。
4. 分别选择另外两个分散地标作为验证点，同样在 Apple 底图取点。验证点不参与拟合；默认误差上限 10 米（可设 1–30 米）。三个点需两两相距 ≥50 米，三角形高度 ≥20 米，避免集中或共线。
5. 所有检查通过后导出 CAMAP 和单独 JSON 校准记录。只更新对应 frame 的 mapkit 绑定和 frame revision；amap、几何、地标 UUID、主图 ID、发布基准与其他 frame 均保留。记录保存输入哈希、三对观测点、候选/结果及各验证误差。两次系统保存对话框分别选择输出位置。
6. 用学校端上传草稿，核对只有 frame 绑定变化、106 条既有商户关联继续沿用，再按现有发布流程发布新版本；工具本身不写生产数据库。

默认按 amap 为高德原生 GCJ-02 仅反算一次作为候选。已有 mapkit 时优先使用已有绑定；只有确认源 amap 数值被人为写成 WGS-84 时才选“跳过反算”。切换源假设或区域会清空观测。

Apple 观测点直接来自 `MKMapView.convert(_:toCoordinateFrom:)`，不再做 GCJ/WGS 转换。验证的是当前 Apple 底图视觉对应，不保证 GPS 测绘精度。近似反算数值、自身正反算闭环、临时居中都不能充当独立验证点。误差超限时先查同点选择和源坐标系，再另行评估旋转/比例；本工具不自动调整这两者。
